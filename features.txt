# OPEN FEATURES
 1. minimap/radar view

 2. simulation

 3. edge labels

 4. Command-based history system — replaces closures with serializable command objects + snapshots. This is foundational: it unblocks simulation (you
		can replay command streams), persistence (serialize state), and multiplayer (sync commands). There's already a skill for this.

 5. Node type plugin/registry system — open up NodeType to a registry where each type declares its own: layout rules, handle config, rendering
		delegate, prop schema, reparenting constraints, default textures. This is the single most important architectural change for adding
		sliders/dropdowns/etc without touching 6 files each time.

 6. Animation/tweening engine — a lightweight tween system (not a full physics engine) that can drive: edge label position along edge paths, node
		position transitions, edge pulse/glow effects, camera smooth pan. This feeds into both the "handle-to-handle animation" feature and simulation.

 7. Node buttons — the feature already tracked in features.txt. These are interactive click targets on node headers (max 3), which will be the pattern
		 for future interactive node primitives like sliders.

 8. subgraphs — a re-usable family of primitives that can be collapsed/viewed as ordinary nodes
 9. type propagation — input and output types are inferred on connection to determine compatible types, validations rules are then inferred by the editor before runtime

- EVENT ACTIONS (undoable/redoable):
	* connection
	* deletion (node, edge, groupnode, composition)
	* creation (node, edge, groupnode, composition)
	* world-space translation (whether individual drags or in a multi-selection)
	* node prop change
	* label update
	* re-parenting
	* exporting selections to sub-graphs
	* group node locking/unlocking
    * [others not yet mapped out]

- TEXTURE BUTTON ACTIONS (the events that canvas triggers)
	* edit
	* delete
